| 项 | 内容 |
| --- | --- |
| 版本 | v0.3（一页 PRD，经 AI 产品评审后修订） |
| 状态 | 待评审（**含前置验证任务，见第 9 节；前置任务不通过则不进入开发**） |
| 负责人 | AI 产品经理 |
| 日期 | 2026-09-23 |

## 1. 背景与问题

- **需求来源**：本版需求来自**单一用户（本人，PM 兼项目经理）的自我观察**，属"个人效率工具"假设。是否扩展为团队产品（10 人规模）**尚未验证**，见第 9 节。
- **现状**：作为产品经理兼项目经理，每周涉及 8+ 场会议（内部需求评审、项目会议、外部协作沟通），纪要靠人工整理，整理完还需手动录入钉钉多维表格来记录待办、跟进任务，单场耗时 20–40 分钟；会后 24h 内能产出纪要的比例不足 50%。
  - *数据来源：本人 2026 年 9 月两周（16 场会议）手工记录，非全量统计，属估算。*
- **痛点**
  - 没人愿意当记录员，会议中专注度被牺牲；
  - 行动项散落在聊天记录/记忆里，"谁在什么时候做什么"经常漏掉；
  - 同一份待办要维护两遍：先写成纪要，再手动录进钉钉多维表格，重复劳动且容易漏录；
- **竞品与替代方案**：钉钉"闪记"、飞书"妙记"、通义听悟、腾讯会议 AI 小助手、Otter、Notta 均已提供"录音 → 转写 → 纪要 / 待办"。**本产品所在工作流已在使用钉钉生态，最大的替代方案就在现有工具内部，且可能免费。**
  - **为什么不用现成的**：① 现有工具产出的行动项是**自由文本**，无法直接落到钉钉多维表格的"任务 / 负责人 / 截止时间 / 状态"字段，仍要人工转录；② 现有工具不区分"AI 推断的负责人"与"原文明确指派的负责人"，PM 无法快速核验；③ 需要跨平台（钉钉会议 + 腾讯会议 + 线下会）统一沉淀到同一张表。
  - ⚠️ **【待确认】以上三条差异是否足以支撑自建，必须在动手前用 1–2 天做竞品实测验证；若结论不成立，本项目应终止或降级为个人脚本。**
- **机会**：ASR + LLM 已能把"转写 → 摘要 → 结构化抽取"串成一条低成本流水线，把会后整理从 30 分钟压缩到 3 分钟审核。
- **不做什么**：本版不做实时转写与实时行动项抽取（v1.1 再评估，见第 9 节）；不做会议机器人入会与会议托管；不做项目管理工具本身（只做纪要产出与交付）。

## 2. 目标用户

| 优先级 | 用户 | 核心诉求 |
| --- | --- | --- |
| 核心 | 会议组织者（项目经理 / 产品经理 / 团队负责人） | 快速掌握决议与待办，跟进不遗漏；纪要能直接落到钉钉多维表格；**能一眼看出 AI 哪些结论是不确定的** |
| 核心 | 参会人（一线执行同学 / 前后端研发 / 业务人员） | 明确自己的任务和时间，少开会；**只看到与自己相关的信息** |
| 次要 | 涉及外部参会方的会议组织者 | 录音前能合规获得对方同意，纪要与行动项可对外发送 |

> 说明：此处用「核心 / 次要」表示**用户**优先级；第 5 节用 P0/P1/P2 表示**功能**优先级。两者不同源，不要混读为"P0 功能只服务核心用户"。

## 3. 核心场景

**场景 A：能现场录音的会（主流程）**

会前在工具内点"开始录音" → **弹窗内必填参会人名单**并确认已获参会人同意 → 会议结束点"停止"，音频保存到本地并自动上传 → 会后产出纪要与行动项草稿 → 人工确认生成终稿。

- 覆盖：内部周会、需求评审、项目对齐会（60 min，8 人，中文）。
- **关键前提：参会人名单必填**（可从钉钉群 / 日历一键带出）。名单缺失时不做负责人推断，行动项负责人一律标"待确认"。

**场景 B：只有录音文件的会**

会议已结束，或录音由他人转交（手机录音、会议系统导出文件）。上传文件；若同时提供参会人名单则尝试匹配负责人，否则仅抽取行动项文本。

- 覆盖：补录、外部会议代传、跨平台（腾讯会议 / Zoom）导出的录音。

**场景 C：外部会议（合规特例）**

涉及客户 / 合作伙伴。除场景 A 的流程外，**必须显式告知对方并记录告知时间与方式**（见第 8 节）。

> 本版所有场景均为**会后异步产出**：录音只负责"把会录下来"，转写与抽取都在会议结束后进行，不做实时（见第 9 节）。

## 4. 用户故事

- 作为**项目经理**，我希望会议结束后能直接拿到带决议和行动项的纪要草稿，这样我不用再花 30 分钟整理。
- 作为**项目经理**，我希望纪要和行动项能一键导出到钉钉多维表格，这样我不用再手动录一遍待办。
- 作为**会议组织者**，我希望开会时能在工具内一键录音、结束后自动进入转写流程，这样我不用另找录音软件再手动上传。
- 作为**会议组织者（涉及外部参会方）**，我希望录音前能方便地告知并获得对方同意，这样我用起来没有合规顾虑。
- 作为**参会人**，我希望事后也能补录并拿到纪要，这样没来得及记录的会也不会漏。
- 作为**参会人**，我希望收到只包含"我的任务"的提醒，这样我能立刻知道要做什么、什么时候交。
- 作为**项目经理**，我希望一眼看出 AI 哪些结论是**推断的**、哪些是原文明确的，并能点回原文核对，这样我才敢直接采用，而不必逐条重听录音。
- 作为**会议组织者**，我希望纪要默认只有我能看到、并能显式指定分享给谁，这样会议内容不会意外外泄。
- 作为**参会人**，我希望只看到与我相关的行动项、看不到与我无关的敏感讨论，这样我能放心使用。

## 5. 功能清单

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| F0 | 权限与可见性 | 纪要默认仅上传者可见；可显式分享给指定参会人；行动项提醒只发给被指派者；分享记录可查 | P0 |
| F1 | 现场录音 | 会议中开始 / 结束录音；**开始前弹窗内必填参会人名单 + 强制确认已获参会人同意**；录音中显示"录音中"提示 | P0 |
| F2 | 录音失败恢复 | App 崩溃 / 断电后音频可恢复或续录；异常退出后给出明确提示（已恢复时长） | P0 |
| F3 | 音频上传 | mp3/wav/m4a，单文件 ≤ 2h / ≤ 500MB，支持拖拽与**断点续传** | P0 |
| F4 | 语音转写 ASR | 带时间戳与说话人分离（speaker diarization），中文优先 | P0 |
| F5 | 说话人标定 | 把 `SPEAKER_1/2/3` 映射为人名：首次说话时提示从参会人名单中点选，一次绑定全程复用；未标定的显示为"说话人 A" | P0 |
| F6 | 转写文本校对 | 可编辑转写文本后再生成纪要（校正人名、术语、口音误识） | P0 |
| F7 | 纪要生成 | 摘要、议题、决议、待确认问题 | P0 |
| F8 | 行动项抽取 | 任务 + 负责人 + 截止时间 + 置信度。**时间边界：只抽显式时间与可归一化的相对时间（"周五前"→具体日期）；"尽快 / 下周再说"等模糊表达一律进 `open_questions`，不猜** | P0 |
| F9 | 结论来源标注 | 标注结论来源：`名单匹配` / `上下文推断` / `未识别`，并给出置信度；**推断结果不自动指派** | P0 |
| F10 | 置信度可视化与溯源 | 高 / 中 / 低三档着色；点击行动项跳转到原文对应时间戳（`evidence_ts`）与原始引文 | P0 |
| F11 | 结果编辑与确认 | 可改文本、指派、改期；确认后生成终稿，**并记录编辑量**（供第 7 节"纪要可用率"统计） | P0 |
| F12 | 导出到钉钉多维表格 | 行动项按"任务 / 负责人 / 截止时间 / 状态"字段写入；**负责人需映射为钉钉 userid**（人名 → userid，同名需用户确认）；无 API 权限时降级为可直导 CSV | P0 \* |
| F13 | 通用导出 / 分享 | Markdown、邮件、复制到剪贴板、Webhook | P1 |
| F14 | 个人待办聚合 | "我的任务"视图，按截止时间排序 | P1 |
| F15 | 术语表 / 热词 | 上传公司专有名词提升识别准确率 | P2 |

> \* **F12 的优先级取决于钉钉开放平台 API 可行性预研结论**（见第 9 节前置任务）。若拿不到多维表格写权限，F12 降为 P1，仅保留 CSV 导出，第 7 节的对应指标同步下调。
> 表格已按优先级排序。**本版不含任何实时（流式）能力**，实时转写与实时行动项归入 v1.1。

## 6. AI 输入与输出

**输入**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| audio_file | file | 是 | 会议录音（工具内现场录制或外部录音文件上传） |
| consent_confirmed | boolean | 是 | 已获得参会人同意；**现场录音在"开始录音前"确认**，上传场景在上传前确认（外部会议另需告知记录，见第 8 节） |
| attendees | string[] | 是（场景 A） | 参会人名单。**现场录音必填**，用于说话人标定（F5）与负责人匹配（F9）；缺失时不做负责人推断 |
| meeting_meta | object | 否 | 会议主题、会议日期与时间（**相对时间归一化的锚点**） |
| glossary | string[] | 否 | 专有名词、人名、缩写（不提供时依赖 ASR 通用模型） |

**输出（JSON）**

```json
{
  "meeting": { "title": "产品周会", "date": "2026-09-22", "duration_min": 62 },
  "speakers": [
    { "speaker": "SPEAKER_1", "name": "张三", "binding": "user_confirmed" }
  ],
  "summary": "3-5 句会议摘要",
  "topics": [{ "title": "议题名", "points": ["..."], "conclusion": "结论" }],
  "decisions": [{ "text": "决议内容", "evidence_ts": "00:12:30" }],
  "action_items": [
    {
      "task": "输出 Q4 迭代排期表",
      "owner": "张三",
      "owner_source": "context_infer",
      "owner_confidence": 0.86,
      "due_date": "2026-09-25",
      "due_source": "relative_from_meeting_date",
      "due_confidence": 0.78,
      "priority": "high",
      "evidence_ts": "00:41:12",
      "raw_quote": "张三你周五前把这个排期表发出来"
    }
  ],
  "open_questions": [
    { "text": "竞品报告的截止时间未明确（原话：\"尽快吧\"）", "evidence_ts": "00:52:03" }
  ]
}
```

**质量约束**

- 输出必须为合法 JSON；行动项须带原文引用与时间戳（可溯源）；
- **负责人与截止时间必须带来源标注**（`owner_source` / `due_source`）；无法确定时填 `null` 并写入 `open_questions`，**禁止编造人名和日期**；
- **不推断模糊时间**："尽快 / 下周再说 / 这个迭代内"一律进 `open_questions`，`due_date` 填 `null`；
- 若用户校对过转写文本（F6），纪要与行动项必须以**校对后**的文本为输入；
- 本版**仅支持中文会议**，不做语言自动识别与双语输出（多语言见 v1.2）。

## 7. 评估指标

**北极星指标：端到端人工净耗时（P50）≤ 8 min**

- **定义**：从"停止录音 / 上传完成"到用户点击"确认终稿"期间，**用户实际操作与阅读的全部时间**（含校对、改指派、导出）。
- **为什么用这个**：本产品价值 = 原人工耗时 30 min −（机器等待 + **人工校对** + 导出）。**只统计机器耗时会严重高估收益**——生成只要 5 min，但逐条核对 8 条行动项的负责人和日期可能还要 5–10 min。
- **若这个数字做不到明显低于 30 min，产品核心假设不成立。**

| 类型 | 指标 | 测量口径（公式 / 数据来源 / 判定人） | MVP 目标 |
| --- | --- | --- | --- |
| 北极星 | 端到端人工净耗时（P50，60 min 会议） | 埋点：`确认终稿时间 − 停止录音时间 − 机器处理时长`；来源：客户端埋点；判定人：无（客观） | ≤ 8 min |
| 质量 | 行动项召回率 | 标注集：50 场真实会议（内部 45 + 外部 5），双人独立标注，一致性 Kappa ≥ 0.7；分母 = 标注集行动项总数；判定人：本人 + 1 名同事 | ≥ 85% |
| 质量 | 行动项精确率 | 同上标注集；分母 = AI 抽出的行动项总数 | ≥ 80% |
| 质量 | 负责人识别准确率 | **仅统计已识别出负责人的条目**（`owner` 非 null）；分母 = 该子集条数 | ≥ 85% |
| 质量 | 负责人"留白正确率" | 应对"该标待确认的有没有标"：分母 = 标注集中**原文未明确指派**的条目 | ≥ 90% |
| 质量 | 截止时间识别准确率 | **口径限定：仅统计原文含显式时间或可归一化相对时间的行动项**；"尽快"类模糊表达不计入本指标（一律计为 `open_questions`） | ≥ 75% |
| 质量 | 纪要可用率 | 判定规则：终稿相对草稿的**编辑率（编辑字符数 / 草稿字符数）≤ 15%** 视为"可用"；来源：F11 记录的编辑量 | ≥ 70% |
| 质量 | 幻觉率 | 判定规则：终稿中**既无 `raw_quote` 支撑、也无法在转写文本中定位到近似表述**的行动项占比；双人判定 | ≤ 3% |
| 效率 | 上传到产出 P50 时长（60 min 会议） | 埋点：`草稿生成时间 − 上传完成时间` | ≤ 5 min |
| 效率 | 录音"停止 → 草稿"P50 时长 | 埋点：`草稿生成时间 − 停止录音时间`（含自动上传） | ≤ 8 min |
| 效率 | 录音时长完整性 | `(音频时长 − 会议实际时长) / 会议实际时长`；来源：录音元数据 vs 会议日历时长 | ≤ 2% |
| 效率 | 录音文件生成成功率 | `成功生成可播放文件的录音数 / 开始录音数` | ≥ 99% |
| 产品 | 钉钉多维表格导出成功率 | `成功写入条数 / 尝试写入条数`；判定人：无（客观） | ≥ 98% |
| 产品 | 导出后人工修正字段率 | `被手动修正的字段数 / 写入字段总数`（衡量"人名 → userid"等映射质量） | ≤ 10% |
| 产品 | 小样本复用判断 | 10 人试用组中，**第 3 周仍主动使用 ≥ 2 次**的人数。*10 人样本下不统计留存率百分比，无统计意义* | ≥ 7 / 10 人 |
| 成本 | 单场会议总成本（60 min 会议） | 拆分为 **ASR 成本 + 说话人分离成本 + LLM 成本**，按实际 API 账单统计；60 min 与 2h 需分别核算 | ≤ ¥1.5 |
| 守护 | 数据泄露事件数 | 未经分享而被他用户看到的纪要数量（权限测试用例 + 线上审计） | 0 |

## 8. 风险与合规

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| **内部会议录音未获同意** | 高 | 开始录音前弹窗**强制确认**已获参会人同意；录音全程界面显示"录音中"标识；不做静默 / 后台录音 |
| **外部会议录音未获同意** | 高 | ⚠️ 界面提示对**外部参会方无效**（对方看不到你的屏幕）。必须**显式告知**：① 提供会前告知话术一键复制；② 记录告知时间与方式，存证可查 |
| **"用户勾选"≠ 法律合规** | 高 | ⚠️ 本版 `consent_confirmed` 是**录入者自证**，属"风险自担"的降级方案，**不构成参会人同意的证据链**。若面向企业 / 客户会议推广，需升级为参会人侧确认（入会提示音 / 会前邮件确认） |
| 个人隐私 / 敏感信息 | 高 | 云端：传输与存储加密（TLS + AES-256）、**音频默认 30 天自动删除**、"不训练"开关；**纪要文本与行动项长期保留，由用户主动删除**（否则与"长期跟进"的核心诉求冲突）；本地：录音存于用户设备，明确提示"由用户自行管理 / 删除" |
| 会议内容越权访问 | 高 | 纪要默认仅上传者可见（F0）；分享需显式指定人员；上线前完成权限越权测试用例（对应第 7 节"数据泄露事件数 = 0"） |
| 幻觉（编造负责人 / 日期） | 高 | 强制原文引用 + 时间戳，F10 支持点击跳转核验；标注 `owner_source` / `due_source`；低置信度不自动指派（F9） |
| 第三方 ASR 数据出境 | 中 | 优先境内节点；企业版提供私有化部署选项 |
| 识别准确率不足 | 中 | 术语表 + 热词（F15）；提供转写文本校对后再生成纪要（F6） |
| 成本失控（长音频） | 中 | 单文件时长上限；**成本需按 60 min / 2h 分别核算，2h 会议可能突破 ¥1.5/场**；异步队列 + 分片并发 |
| 录音过程中断（崩溃 / 断电） | 中 | F2 音频可恢复或续录；异常退出后明确提示已恢复时长 |
| 被当作"监控工具"引发抵触 | 中 | 录音全程界面显示"录音中"标识（F1）；纪要默认对参会人透明可见 |

## 9. MVP 范围

**动手前的前置任务（1–3 天；先做这两个，结论可能直接改变范围）**

1. **竞品实测（1–2 天）**：用钉钉"闪记" / 通义听悟跑 3 场真实会议，逐条对照第 1 节的三条差异点。**若差异不成立，项目应终止或降级为个人脚本，不应进入 6–8 周开发。**
2. **钉钉开放平台 API 可行性预研（1 天）**：确认多维表格是否可写、人员字段能否通过 userid 写入。**结论决定 F12 是 P0 还是 P1。**

**做（P0 功能，见第 5 节；工期 6–8 周）**

- F0 权限与可见性
- F1 现场录音（含参会人必填 + 同意确认）+ F2 录音失败恢复 + F3 音频上传（含断点续传）
- F4 语音转写（时间戳 + 说话人分离）+ F5 说话人标定 + F6 转写文本校对
- F7 纪要生成 + F8 行动项抽取（含时间边界规则）+ F9 结论来源标注 + F10 置信度可视化与溯源
- F11 结果编辑与确认（含编辑量埋点，供第 7 节指标使用）
- F12 导出到钉钉多维表格（**取决于预研结论**；降级时仅保留可直导 CSV）
- F13 通用导出：Markdown / 复制到剪贴板
- 云端音频 30 天自动删除 + 本地文件管理提示 + 合规确认闸门

**不做（放到后续版本）**

- **实时转写、实时行动项抽取**（v1.1）
- 会议机器人入会、日历自动触发录音（v1.1）
- 日历 / 飞书 / 钉钉 / CRM 双向同步（v1.1，本版只做单向写入钉钉多维表格）
- 个人待办聚合视图与提醒（v1.1，即 F14）
- 参会人侧同意确认（入会提示音 / 会前邮件确认，v1.1；本版依赖录入者自证）
- 多语言双语纪要、术语表（v1.2，即 F15）
- 私有化部署（企业版单独排期）

**决策记录**

- 本版定为"只录音、会后异步转写"（A 方案）。实时转写依赖独立的流式架构与成本模型，且会改变会议节奏与交互设计；MVP 先跑通"录音 → 转写 → 纪要 → 导出钉钉"闭环。
- 本版按**"个人效率工具"假设**设计。若要升级为团队产品，需先验证：其他成员的会议类型是否类似、是否愿意录音、是否同样使用钉钉多维表格。**验证不通过则不上线团队版本。**

**验证方式**：招募 10 名内部用户，跑 30 场真实会议（其中 ≥ 5 场涉及外部参会方，用于验证合规流程与告知记录），以第 7 节指标做基线评估。

**上线判定标准**：**北极星指标（端到端人工净耗时 ≤ 8 min）与幻觉率（≤ 3%）两项同时达标**，才进入扩量；任一项不达标，则回到前置任务重新评估，不扩量。
