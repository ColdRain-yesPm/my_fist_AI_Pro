## 二、执行说明

**数据准备**

- 本 10 条用例的输入应取自 PRD §7 要求的**标注集**（50 场真实会议，内部 45 + 外部 5）。
- TC-01 / TC-03 / TC-04 / TC-05 / TC-07 / TC-10 可用**合成音频**（按脚本朗读录制）先行验证，但正式判定必须用真实会议录音。
- 每条用例需准备**金标准标注**（正确的行动项清单 + 负责人 + 截止时间），由 2 人独立标注，一致性 Kappa ≥ 0.7。

**判定方式**

- 每条用例记录：`是否通过` / `实际值` / `目标值` / `失败原因`。
- 涉及"幻觉"的判定规则（引自 PRD §7）：**终稿中既无 `raw_quote` 支撑、也无法在转写文本中定位到近似表述的行动项**，计为幻觉。
- 涉及"待确认"的判定规则：`owner = null` 且 `owner_source = unrecognized`，且不得出现在任何自动指派/通知中。

**环境**

- 场景 A（现场录音）：F1 入口，含参会人必填 + 同意确认。
- 场景 B（文件上传）：F3 入口。

| 类型 | 正常 |
| 对应需求 | F4 语音转写、F7 纪要生成、F8 行动项抽取、F9 来源标注 |
| 前置条件 | 场景 A；参会人名单已录入 8 人：张三、李四、王五、赵六、钱七、孙八、周九、吴十 |

**输入**（60 min 中文会议，无重叠语音、无背景噪声，脚本中含且仅含 3 个明确行动项）

| # | 原话 | 期望负责人 | 期望截止时间 |
| --- | --- | --- | --- |
| 1 | "张三，你周五前把 Q4 排期表发出来" | 张三 | 2026-09-25 |
| 2 | "李四负责把埋点方案同步给测试，下周三之前" | 李四 | 2026-09-30 |
| 3 | "王五会后整理一下客户反馈，最晚 9 月 30 号" | 王五 | 2026-09-30 |

**预期结果**

- `action_items` **恰好 3 条**（不多不少）。
- 每条字段齐全：`task` / `owner` / `owner_source` / `owner_confidence` / `due_date` / `due_source` / `evidence_ts` / `raw_quote`。
- 3 条 `owner` 全部正确；`owner_source` 为 `roster_match` 或 `context_infer`。
- 3 条 `due_date` 归一化正确（相对时间已按会议日期换算）。
- `evidence_ts` 与实际出现位置误差 **≤ 5 s**。
- **幻觉数 = 0**：3 条 `raw_quote` 均能在转写文本中定位到。
- 输出为合法 JSON，符合 PRD §6 结构。

**判定标准**

| 指标 | 目标 |
| --- | --- |
| 行动项召回率 | 100%（3/3） |
| 行动项精确率 | 100%（3/3） |
| 截止时间识别准确率 | 100%（3/3） |
| 幻觉率 | 0% |

> **本用例是基线用例，不通过则后续所有用例结果不可信。**

### TC-03　边界：多人抢话 / 重叠语音

| 项 | 内容 |
| --- | --- |
| 类型 | 边界 |
| 对应需求 | F4 说话人分离、F5 说话人标定 |
| 前置条件 | 场景 A；参会人名单已录入 |

**输入**

- 60 min 会议，包含 **≥ 5 处 3 人以上同时说话**（抢话）片段，每处持续 ≥ 10 s。
- 在抢话片段中**故意安排 1 个行动项**（如多人同时插话里有人说"这个我来吧"）。

**预期结果**

- 抢话片段允许说话人分离降级：标注为"重叠 / 说话人不确定"。
- **非抢话时段（≥ 90% 时长）说话人归属正确。**
- 抢话片段里的行动项**不得因抢话而丢失**（要么抽出，要么进 `open_questions`，不能消失）。
- **关键否决项：不得因为听不清而编造负责人**——无法确定时必须标"待确认"。

**判定标准**

| 指标 | 目标 |
| --- | --- |
| 行动项召回率（本用例） | ≥ 75%（允许因抢话下降，但不得低于基线的 75%） |
| 幻觉率 | ≤ 3% |
| 非抢话时段说话人归属正确率 | ≥ 90% |

### TC-06　对抗：玩笑话不能当真

| 项 | 内容 |
| --- | --- |
| 类型 | 对抗 |
| 对应需求 | F8 行动项抽取、F9 来源标注（防"把情绪表达当承诺"） |
| 前置条件 | 场景 A；参会人名单已录入 |

**输入**

- **主场景**：会议中 A 说：**"这个需求再改我就明天辞职了啊，哈哈哈"**，全场笑，后续议题未再提及此事。
- **变体场景（同一用例内追加验证）**：另一处 A 说：**"这个需求再改我就明天辞职，但排期表我周五前给你"**。

**预期结果**

- 主场景：
  - **不产生**任何与"辞职 / 离职"相关的 `action_items`。
  - **不写入** `decisions`。
  - 不产生任何形式的自动提醒或指派。
- 变体场景：
  - 必须抽出**"周五前给排期表"**这一条，负责人 = A。
  - 前半句的情绪表达**不得**成为行动项，**也不得**因为前半句而丢掉后半句的真实承诺。

**判定标准**

| 指标 | 目标 |
| --- | --- |
| 主场景误抽条数 | **0 条** |
| 变体场景召回率 | 100%（1/1，不得因情绪表达干扰而漏抽） |
| 变体场景误抽条数 | 0 条 |

> **本用例是"玩笑 vs 承诺"的判别核心**：判据不是内容像不像待办，而是**是否存在可执行的交付物 + 承诺方**。

### TC-09　长会议：2 小时录音的延迟与完整性

| 前置条件 | 场景 A；120 min 音频，含 15 人、跨部门、≥ 3 处长时间无人发言 |

**输入**

- 120 min 音频（mp3，约 110–140 MB）。
- 变体：121 min 音频（**超出 2h 上限**）。

**预期结果**

- 正常流程：
  - 录音时长完整性偏差 **≤ 2%**。
  - **"停止录音 → 纪要草稿"耗时 ≤ 25 min**（按 60 min→8 min 线性外推 + 分片并发余量；**该阈值需 PM 确认，PRD 目前只定义了 60 min 场景**）。
  - 处理全程**有进度反馈**（转写 % / 当前阶段），不允许无提示等待。
  - 20 min 以上无发言的静音段不产生任何输出内容，也不报错。
- 变体（121 min）：
  - **在开始录音时即提示上限**（而不是录完再拒绝）。
  - 若已超限，给出明确提示并**保留已录部分的音频**。
- 失败恢复：任务失败后可重试，**不产生重复纪要、不重复计费**。

**判定标准**

| 指标 | 目标 |
| --- | --- |
| 录音时长完整性 | ≤ 2% 偏差 |
| 停止录音 → 草稿 | ≤ 25 min（待确认） |
| 进度反馈 | 100% 可查 |
| 超限处理 | 事前提示，0 次"录完才拒绝" |
| 重试重复产出 | 0 条 |

## 五、本用例集暴露的 PRD 空白（需先补，否则 TC-08 / TC-09 无法判定）

1. **脱敏的作用范围未定义**（影响 TC-08）：打码是只作用于**纪要/导出内容**，还是也作用于**转写原文**？薪酬、健康信息是"打码"还是"完全不进纪要"？规则必须先定，否则"脱敏是否通过"无法判定。
2. **2h 场景的延迟阈值未定义**（影响 TC-09）：PRD §7 只有 60 min 会议的指标（≤ 8 min）。2h 会议的阈值需要单独定。
3. **同名 / 非参会人的处理规则未定义**（影响 TC-02、TC-07、TC-10）：人名 → userid 遇同名怎么办、非参会人是否允许写入钉钉人员字段，PRD 只写了"同名需用户确认"，未定义非参会人的降级策略。
